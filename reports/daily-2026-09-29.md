## What Could Have Been Improved — Failures & Lessons

### Failure 1: Safety Gate Ran AFTER Injection (Critical)
**What happened:** The original safety gate used hardcoded 6 topics and ran *after* content was already injected into 60 .njk templates. 25 of 29 topics had critical issues (11 with raw code fences, 14 missing analysis files, 1 too short).

**Impact:** Had to fix 11 files post-injection. 2 files (blockchain, cyber-security) were nearly blanked to 0 bytes during fence stripping. Required `git restore` + a second, more precise fix script.

**How to prevent next time:**
- Safety gate ALWAYS runs with `--pre-injection` before any template modification
- Dynamic topic discovery (scan `research-data/langchain/*/enhanced-content.md`) — never hardcode topic lists
- Pipeline order documented in skill: Firecrawl → LangChain → Safety Gate (pre-injection) → Inject → Build → Safety Gate (post-injection) → Deploy

### Failure 2: Inject Script Had No Sanitization (Critical)
**What happened:** `inject-enhanced-content.py` blindly inserted raw `enhanced-content.md` content into .njk templates. Markdown code fences (` ```markdown ... ``` `) rendered as raw text on live pages.

**Impact:** 11 pages had visible code fences on the live site. The consulting page had a 440-line raw markdown leak.

**How to prevent next time:**
- `sanitize_content()` is now mandatory in the injection path — strips fences, enforces single H1, removes raw notes
- `--dry-run` flag available to validate without modifying
- Injection skipped entirely if sanitization fails

### Failure 3: Two Files Blanked to 0 Bytes During Fix (Critical)
**What happened:** The first fence-fixing script (`fix-fences.py`) used an overly broad regex that matched the entire file content and replaced it with empty string. `blockchain/enhanced-content.md` and `cyber-security/enhanced-content.md` went to 0 bytes.

**Impact:** Had to `git restore` both files, then write a more precise fix script (`fix-fences-v2.py`) that only strips fence delimiters, not content between them.

**How to prevent next time:**
- Always test sanitization scripts on a COPY first (`--dry-run` flag)
- Use precise regex: strip only `^```markdown$` and `^```$` lines, not `.*`
- Verify file size before and after: `wc -c` should never decrease by more than fence delimiter bytes

### Failure 4: Progress State Lost During Context Compaction (High)
**What happened:** Hermes's context compressor truncated the conversation, losing track of which pages had been processed. Work had to be partially reconstructed from git history.

**Impact:** Time lost reconstructing state. Risk of double-processing or missing pages.

**How to prevent next time:**
- `research-data/progress.json` now tracks every page's status (pending → firecrawl_done → langchain_done → injected → verified)
- File survives context compaction — it's on disk, not in conversation
- Schema includes chunk-level status, commit hashes, and safety gate results

### Failure 5: n8n Never Started — Pipeline Run Manually (Medium)
**What happened:** 3 JSON workflow files existed but n8n was never started or imported. The entire pipeline was executed manually through Hermes tools.

**Impact:** No automation. Every step required manual orchestration. No repeatable pipeline.

**How to prevent next time:**
- n8n is now running (localhost:5678) and the v3 workflow is imported (11 nodes)
- Still needs: credential configuration in n8n UI (OmniRoute HTTP auth), then workflow activation
- Next run should be triggered from n8n, not Hermes

### Failure 6: LangChain Enhanced Only 32/72 Pages (Medium)
**What happened:** LangChain only processed 32 of 72 pages. The remaining 40 got Firecrawl-only content (raw snapshots, no LLM enhancement).

**Impact:** 40 pages have lower-quality content. The FastAPI server at localhost:8080 can enhance them but wasn't called for all pages.

**How to prevent next time:**
- Run LangChain on ALL pages before the safety gate, not just a subset
- The n8n workflow's "Pick Topics" node should enumerate all 72 page topics, not just 32
- Add a coverage check: `ls research-data/langchain/ | wc -l` should equal 72

### Failure 7: World Map Was Random Blobs (Medium)
**What happened:** The world map SVG was generated with random shapes that didn't match any real geography. KSA was misplaced, UAE was obscured by overlapping shapes.

**Impact:** Visual credibility damage on the homepage. Only caught because a screenshot was taken.

**How to prevent next time:**
- Never generate geographic SVG paths from scratch — use known path data (amCharts, simplemaps)
- Visual QA after each chunk: screenshot 2-3 sample pages, not just the homepage
- Fixed with 228 lines of accurate SVG path data (35 path elements)

### Failure 8: delegate_task Timeouts on Bulk File Edits (Low)
**What happened:** Using `delegate_task` (subagents) for mechanical multi-file edits (e.g., adding icons to 25+ pages) timed out twice at 12 minutes each.

**Impact:** Time wasted waiting for subagent timeouts. Had to fall back to `execute_code` with a Python loop.

**How to prevent next time:**
- Never use subagents for mechanical edits — use `execute_code` with Python `re.sub` loop
- `delegate_task` is for reasoning-heavy subtasks, not file pattern matching
- A Python loop processes 25 files in ~0.5s vs 12 min subagent timeout

### Failure 9: Duplicate `<main>` Wrapper (Low)
**What happened:** `layout.njk` had a `<main>` wrapper, and page templates also had `<main>` — producing nested main elements.

**Impact:** HTML validation warning. Accessibility tree confusion.

**How to prevent next time:**
- Check for existing elements before wrapping: `grep -c '<main' layout.njk` before adding to templates
- Run HTML validation after build: `npm run build` should catch structural issues
